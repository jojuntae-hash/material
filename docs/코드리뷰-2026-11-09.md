# 코드리뷰 및 검증 기록 · 2026-11-09

대상: GitHub 3eb3ac5 이후 로컬 변경(거래명세표 메뉴 통합, 데스크톱 작성표 폭 확대, 동일 신청자 합산 메모 생략).

## 확인 및 보완
- 거래명세표는 기존 v2.4 HTML/JS/CSS만 포함한다. 실제 엑셀·이미지·data.js·이전 버전은 포함하지 않는다. 폴더 선택·로컬 파일 관리 및 원본 프로그램은 유지한다.
- 메뉴 이동의 미저장 확인을 검토하여 ‘연결 설정’ 이동도 같은 검사를 거치도록 수정했다. 작업 중 메뉴 이동은 차단하고 새로고침/종료에는 beforeunload 경고를 적용한다.
- 백그라운드 공유자료 갱신 시 열린 거래명세표 iframe을 다시 만들지 않는다. 폴더 쓰기는 기존 권한 요청 및 백업 절차를 유지한다.
- 데스크톱 작성표는 1101px 이상에서 화면 폭을 사용한다. 1265/1366/1920 폭의 clientWidth=scrollWidth를 확인했다. 작은 화면은 기존 가로 탐색을 유지한다.
- 합산 신청자가 공백 정규화 후 한 명이면 기존 메모만 보존한다. 여러 신청자의 수량 분해, 총합, 공종 분리, 원본 상세내역은 유지하며 회귀 테스트로 확인했다.

## 검증
- 전체 자동 테스트 101개 통과, Vite 최종 빌드 통과.
- 통합 업무 스크립트 3개 node --check 통과.
- 분리 포트에서 실제 폴더 선택으로 복사본 555문서/3499품목 및 이미지 표시 확인.
- 실제 원본 파일 수정·삭제/복원과 운영 Supabase/Vercel 배포 성공은 이번 검증 범위에 포함하지 않는다.

리뷰 후 현재 범위에서 추가로 확인된 배포 차단 문제는 없다. 사용자 요청으로 GitHub 업로드 보류를 해제하고 소스 및 문서를 main에 반영한다.


### Vercel 내부 화면 차단 보정 (2026-11-09)
운영 거래명세표 HTML 응답200 및 X-Frame-Options DENY를 확인했다. 기존 전역 DENY 때문에 같은 출처 iframe도 차단됐다. /statements/ 경로만 SAMEORIGIN 및 CSP frame-ancestors self를 적용하고 다른 경로는 DENY를 유지한다. SPA fallback에서 statements 경로를 제외해 HTML/JS 자산을 직접 제공한다. 배포설정 회귀 테스트를 추가했다. 로컬 빌드는 운영 응답 헤더를 적용하지 않으므로 GitHub 반영 뒤 실제 배포 헤더를 확인해야 한다.


### 거래명세표 전체 화면 연결 (2026-11-09)
같은 출처 헤더 수정 후에도 사용자 환경에서 내부 프레임 차단이 계속돼 메뉴 진입을 같은 탭의 거래명세표 HTML 전체 화면 이동으로 변경했다. 내부 iframe을 생성하지 않으며 상단 돌아가기 링크로 자재청구 관리에 복귀한다. 로컬 확인 모드도 복귀 시 유지한다. 기존 미저장 및 작업 중 beforeunload 경고·업무 데이터·폴더 선택 방식은 보존한다. 분리 브라우저에서 메뉴 클릭→보관함 표시→돌아가기 동작 및 빌드를 확인했다. 운영 메뉴의 표시 성공은 새 배포 뒤 사용자 확인이 필요하다.


### 거래명세표 네이티브 본문 통합·청구서 좌우 복원 (2026-11-09)
최신 구현: iframe/전체 페이지 이동 대신 자재청구 관리의 왼쪽 메뉴를 유지하는 본문으로 구성했다. src/statement-library의 파일 파서·파일 관리 로직은 기존 프로그램에서 가져오고, app.js는 DOM 조회 대상을 해당 ShadowRoot로 한정하는 mount 함수로 전환했다. 새 native.css와 상단 요약/검색/접는 분류/목록-상세 배치로 화면을 재구성했다. 원본 standalone의 CSS를 불러오거나 HTML의 script를 실행하지 않는다. Shadow DOM은 동일 문서 요소이며 iframe이 아니다.
메뉴를 나갔다 돌아와도 같은 host와 업무 상태를 재사용한다. 문서555장/3499품목 사본 읽기, 검색58건, 이미지 표시, 품목 편집 및 메뉴 복귀 후 미저장 값 보존, 시험 수정 취소를 확인했다. 원본 파일 쓰기·삭제는 이번 검증에서 실행하지 않았다. 모바일390px에서 문서 전체 가로 넘침 없음, 브라우저 오류 로그 없음. 기존 폴더 선택/기억하기/저장/백업 절차와 beforeunload 보호는 유지한다. 업무 로직 변경 시 public/statements의 독립 실행본과 src/statement-library의 통합본을 함께 검토한다.
청구서 작성은 사용자 요청에 따라 데스크톱에서도 검색220px 왼쪽·작성표 오른쪽으로 복원했다. 확인한1265px에서 같은 행 배치와 표의 가로 스크롤0을 확인했다. 넓은 앱 프레임과 비례 열 폭은 유지한다. 이후 사용자 요구가 이 절의 최신 구현에 우선한다.
