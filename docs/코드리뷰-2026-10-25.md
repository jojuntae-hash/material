# 코드리뷰 및 검증 기록

검토일: 2026-10-25 / 대상: 직전 업로드 `9b37018` 이후의 품명 변환·목록 관리 변경과 연결 코드

## 검토 범위

- 기본 33개 품명 변환 규칙, 공백·각도기호 정규화, 전체 이름 일치, 원래 이름 보존
- 검색 결과·직접입력·작성용 엑셀 추가·기존 작성 행에 대한 변환 적용
- 설정의 행 편집·등록·삭제·검색·분류와 조회자 접근 제한
- 품목관리 엑셀 출력·시트 선택·중복 제외·새 별칭 보강·충돌 시 전체 중단
- 기존 batch 저장 구조와 버전·권한 연결, 사용자/모드/현장 간 읽기 결과 혼입 방지
- 청구번호·소장 기본값, 기존 작성·저장 흐름과의 회귀 검증

## 발견 및 수정

| 문제 | 영향 | 수정과 근거 |
|---|---|---|
| 한 규칙의 별칭에 공백·각도기호만 다른 값이 중복 보관될 수 있음 | 목록과 내보내기에 같은 별칭이 반복될 수 있음 | 공통 `uniqueMaterialAliases`를 입력·엑셀 파서·추가 계획에서 사용. 테스트로 정규화 중복 제거 확인 |
| A→B와 B→C, 또는 A→B와 B→A를 함께 등록할 수 있음 | 반복 적용 때 이름이 바뀌거나 되돌아갈 수 있음 | 규칙 검증에서 최종 결과를 재변환하는 연쇄·순환 관계 차단. 기본 33개 규칙의 반복 적용 안정성 확인 |
| 업로드 미리보기의 범위가 현장 ID에만 묶여 있었음 | 같은 현장 ID를 사용하는 다른 사용자·모드 전환에서 늦게 끝난 파일이 남을 가능성 | 사용자·모드·현장 범위를 묶고 파일 순번·화면 존재 여부를 함께 확인 |

규칙 추가 계획은 기존 배열을 복제하여 계산하고, 반영 직전 다시 검증한다. 충돌 시 먼저 계산한 일부 추가 내용도 저장하지 않는다. 빈 배열을 명시적으로 저장한 현장에는 기본 규칙을 다시 덮어씌우지 않는다.

## 검증 결과

- `pnpm test`: **50개 통과**. 기존 업무 기능, 독립 PostgreSQL 권한·격리 테스트, 품명 변환과 엑셀 왕복·중복·충돌·연쇄·순환·원본 보존 포함.
- `pnpm build`: 성공.
- `scripts/qa-request-composer.cjs`: 별도 테스트 브라우저에서 규칙 추가·행 수정·두 번째 별칭·삭제·검색, 목록 다운로드와 신규행 업로드, 같은 파일 재업로드 중복 제외, 변환된 청구서 출력과 기본값 확인 성공. 기존 저장·불러오기·목록 관리·합산 출력 흐름도 포함.
- 테스트 자료와 화면 이미지는 무시되는 `test-results/`에만 보관하며 운영 업무자료를 변경하지 않았다.

## 남은 확인과 주의사항

- 실제 Supabase 운영 계정과 서로 다른 기기의 저장·조회, 운영 Vercel 최신 배포 성공은 검증하지 않았다. 코드 연결·독립 DB 테스트와 구분한다.
- 목록 파일 업로드는 추가 방식이다. 기존 결과·분류를 바꾸려면 행에서 수정한다. 별칭 3개 이상은 보존·엑셀 출력하지만 화면에는 앞의 두 칸과 추가 개수만 표시한다.
- 직접 입력 완료 때 변환하므로 원본 이름을 계속 입력하려면 관리 규칙을 수정해야 한다. 미등록 품명은 유지한다.
- 기본 규칙은 레코드가 없는 현장에만 사용한다. 이후 규칙 JSON을 바꿔도 이미 저장된 현장 규칙은 자동 갱신하지 않는다.
- 이번 검토는 코드와 자동·브라우저 테스트에 기반한 검토이며 모든 운영 환경에 대한 무결함 보증은 아니다.
