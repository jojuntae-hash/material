# 자재명 표준화 통합 계획서

작성일: 2026-11-08  
상태: 계획안 — 이 문서에서는 업무 데이터나 프로그램 동작을 변경하지 않음.

## 1. 목표와 예시

사용자가 동일 자재에 붙인 여러 이름을 하나의 표준명으로 연결한다. 청구내역, 청구서 작성, 자재별 집계, 검색, 관련 엑셀 출력이 같은 규칙을 사용하도록 한다.

| 표준명 | 연결할 별칭 예시 |
| --- | --- |
| 그루브 45도 엘보 | 45˚ 그루브 엘보, 그루브 45 엘보, 그루브 45도 엘보 |
| 그루브 90도 엘보 | 90˚ 그루브 엘보, 그루브 90 엘보 |

표준명의 표기 자체는 사용자가 결정한다. 45도와 90도, 그루브와 나사식 등 실제로 다른 자재는 분리한다. 숫자/단어를 임의로 제거하거나 단어 순서를 바꿔 같다고 추측하지 않는다.

## 2. 현행 코드 확인

- `src/material-names.js`는 표준명(target), 별칭(aliases 배열), 분류(category), 규칙 ID를 이미 지원한다. 공백·각도 기호·대소문자 등의 단순 표기 차이를 정리하고 별칭 충돌과 연쇄 변환을 검증한다.
- `src/material-names-settings.js` / `src/material-names-excel.js`는 관리 화면과 엑셀 가져오기·내려받기를 제공한다.
- `src/request-composer.js`는 검색 결과 추가, 직접 추가, 엑셀 추가, 품명 수정, 현재 작성 목록 규칙 적용에서 이름을 변환한다.
- `src/aggregation.js`의 현행 집계 키는 저장된 품명+규격+단위다. 서로 다른 별칭으로 저장된 과거 청구내역은 하나로 묶이지 않는다.
- 청구내역 조회·검색·다른 메뉴와 공통으로 쓰는 표준화 계층이 없으므로 작성 기능에만 적용되는 불일치가 있다.

## 3. 설정 화면 제안

기존 ‘작성리스트 품목관리’를 ‘자재명 표준화 관리’로 확대한다. 별도의 중복 관리 메뉴는 만들지 않는다.

- 한 항목: 표준명 / 분류 / 별칭 여러 개 / 연결 청구 건수 / 관리.
- 별칭은 개수 제한 2칸 대신 여러 개를 줄 단위 또는 작은 목록으로 추가·수정·삭제.
- 표준명 또는 별칭으로 검색 가능. 기존 규칙과 엑셀 관리 기능은 계승.
- 기존 청구내역에서 아직 연결되지 않은 이름과 사용 건수를 보여주고 표준명을 지정해 별칭으로 등록.
- 비슷한 이름 후보는 제안만 하며 사용자가 확정한 별칭만 적용.
- 변경 전 미리보기: 연결될 원본 이름, 영향받는 건수, 집계 변경 예시. 변경 이력에서 누가 언제 무엇을 바꿨는지 확인.
- 잘못된 표준명으로 연결한 별칭은 해제하거나 다른 표준명으로 이동. 원본 데이터가 남으므로 재계산 가능.

## 4. 공통 처리 방식

한 공통 함수에서 입력 이름을 표준명과 연결 ID로 해석한다. 모든 화면이 이 함수를 사용하고 메뉴마다 별도 치환 코드를 만들지 않는다.

해석 결과 예: 원본명=`45˚ 그루브 엘보`, 표준명=`그루브 45도 엘보`, 표준 자재 ID=해당 규칙 ID, 분류=그루브자재, 연결 상태=등록된 별칭.

기존 규칙의 ID를 안정된 표준 자재 식별자로 활용하되, 현행 규칙 데이터와 충돌·중복 ID를 먼저 검사한다. 표준명 문구가 바뀌어도 동일 자재의 연결이 유지되어야 한다. 원본명과 표준명은 서로 다른 의미로 보관한다.

규칙은 현장별 공유 데이터로 저장한다. 브라우저 localStorage만으로 관리하지 않는다. 현행 batch 기반 규칙 저장을 우선 계승하여 불필요한 DB 마이그레이션을 피하되, 실제 Supabase 저장/권한/동기화 확인 후 스키마 변경 필요 여부를 판단한다.

## 5. 메뉴별 적용

| 영역 | 적용 방식 |
| --- | --- |
| 청구내역 조회 | 표준명 표시, 원본명은 상세에서 확인. 원본명과 표준명/등록 별칭 모두 검색 가능 |
| 청구서 업로드·직접 등록 | 가져오기 검토에서 원본→표준명 확인. 신규 저장 시 원본명과 연결 정보 보존 |
| 청구서 작성 | 자재 검색 결과를 표준명 기준으로 정리. 기존 추가/변환 기능은 공통 함수 사용 |
| 자재별 집계 | 표준 자재 ID+규격+단위 기준으로 집계. 미등록명은 기존 정규화 이름 기준 유지 |
| 자재 전체 청구이력 | 별칭이 다른 과거 청구도 같은 표준 자재의 이력에서 확인 |
| 엑셀 출력 | 업무용 품명은 표준명. 기존 청구서 병합/인쇄범위를 유지. 원본명·연결 정보는 상세 시트에서 보존 |
| 승인목록·업체연락처 | 자재 품명 필드의 연결을 지원. 업체명·담당자·비고 등 자유문장은 치환하지 않음 |
| 공도구 대장 | 자재와 구분된 공도구 품명 영역으로 적용 여부를 제어. 자재 별칭 때문에 공구가 잘못 묶이지 않도록 공통 기술만 재사용 |

수량 합산 자체는 현재 메뉴별 업무 규칙을 유지한다. 자재별 집계는 단위가 다른 수량을 무조건 합치지 않는다. 청구서 합산 다운로드는 기존 사용자 결정인 공종 분리·규격 일치·단위 충돌 처리 및 신청자별 수량 메모를 유지한다. 표준화는 동일 자재를 찾는 기준만 일관되게 만든다.

## 6. 기존 데이터와 검색

추천: 과거 내역의 원본 품명을 일괄 덮어쓰지 않고, 화면과 집계에서 현재 규칙을 적용한다. 규칙 하나를 추가하면 과거 내역도 곧바로 표준명으로 조회된다. 규칙을 해제하면 원래 분리가 가능하다.

다만 이미 청구서 작성 과정에서 변환되어 원본명(originalName)이 남은 데이터는 해당 값을 활용한다. 원본명이 없는 과거 데이터는 임의 복원하지 않는다. 수동으로 확정한 연결과 일반 별칭 자동 연결은 구별하여 규칙 수정 시 우선순위를 명확히 한다.

검색은 관련 별칭을 먼저 표준 자재 ID로 해석한 뒤 규격 등 조건과 함께 평가한다. 화면에서 표준명으로만 묶어 놓고 원본 이름으로 검색하면 안 나오는 불일치를 방지한다. 규칙 저장 후 검색 색인·집계 캐시·선택 상태를 무효화 또는 재연결한다.

공유 데이터가 일부만 로딩된 상태에서는 ‘전체 영향 건수’라고 표시하지 않으며 미리보기와 일괄 확정 작업은 로딩 완료 후 수행한다.

## 7. 오인 연결 방지

- 같은 별칭은 서로 다른 표준명에 중복 등록할 수 없다. 표준명 자체와 다른 규칙의 별칭 충돌도 검사한다.
- 표준명 A→B→C 같은 연쇄 변환과 순환 연결을 금지한다.
- 엘보의 각도, 접속방식, 재질, 압력 등 의미가 다른 조건을 삭제하지 않는다.
- D25/D50 등 규격이 다르면 별도 항목이다. 규격 자동 통일까지 이번 범위에 함께 넣지 않는다.
- 유사도나 AI 제안만으로 기존 데이터를 자동 병합하지 않는다.
- 현장별 규칙과 편집 권한을 지키며 다른 현장/장비 분류에 규칙이 잘못 퍼지지 않게 한다.

## 8. 구현 순서

1. 기존 규칙·원본 보존 현황 점검 → 공통 표준 자재 해석 함수와 충돌 검사 → 별칭 여러 개 관리/영향 미리보기.
2. 청구내역·검색·자재별 집계·전체 이력에 적용. 이 단계에서 기존 청구가 변경 없이 묶여 보이는지 확인.
3. 업로드·직접 등록·청구서 작성·엑셀 출력 연결. 승인/연락처의 품명 연결은 데이터 구조를 확인해 후속 적용. 공도구 영역은 별도 규칙 범위를 검토해 적용.

첫 구현은 1–2단계를 묶는 것을 추천한다. 가장 불편한 ‘같은 부속이 여러 이름으로 검색되고 집계되는 문제’를 우선 해결한다. 현재 작성리스트 변환·엑셀 기능은 회귀 검증하면서 이어 붙인다.

## 9. 완료 판정 예시

- `45˚ 그루브 엘보` 2개 + `그루브 45 엘보` 3개가 같은 규격/단위에서 표준명 한 행 5개로 집계된다.
- 어느 별칭 또는 표준명으로 검색해도 두 원본 내역을 확인할 수 있다.
- 90도 엘보, 다른 규격, 다른 단위는 잘못 합쳐지지 않는다. 취소/삭제 내역 제외 및 기간·공종 필터가 유지된다.
- 규칙 해제/이동/표준명 변경 후 표시와 합계가 일관되게 재계산된다. 원본 이름·수량·청구 이력은 보존된다.
- 신규 업로드와 과거 데이터가 같은 표준명을 사용하며 기계·소방 분리 다운로드와 신청자별 수량 메모가 정상이다.
- 엑셀 규칙 왕복에서 기존 규칙을 중복 생성하지 않고 별칭 추가·충돌을 구분한다.
- 다른 기기에서 같은 현장으로 접속했을 때 규칙이 유지된다. 실제 공유모드 검증과 브라우저 모바일 검증을 별도로 기록한다.
