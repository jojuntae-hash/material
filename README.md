# 자재청구 관리

기계·소방 청구내역, 업체연락처, 자재승인목록을 PC와 휴대폰에서 관리하는 반응형 웹 프로그램입니다.

## 포함 기능

- 공종·기간·품명·규격·업체·신청자·작업위치 검색, 페이지 이동, 검색 결과 엑셀 출력
- 업체연락처는 공종·품목·제조사·대리점·전화·팩스·담당자/비고를 보여 주는 리스트. 전화·팩스는 대리점에 연결하며 품목 행별 차이를 유지
- 청구내역·업체연락처·승인목록 등록 및 수정, 원본 비교, 수정 사유·이력, 이전 값으로 되돌리기
- 엑셀 정리표/본사 청구서 업로드, 시트·수량 열·전체 열 연결 확인, 행별 수정·선택, 중복 후보 확인, 보류 검토 이어하기
- 업체 별칭 연결, 승인 품목과 제조사 연결, 승인 내용 변경 버전 및 증빙 보관
- 비고의 `원자재/대리점` 분리, 역할별 정식 명칭·검토된 별칭·유일한 약칭 연결. 분수·일반 메모·복수 후보는 자동 확정하지 않음
- 모바일 청구 화면의 요약·등록 영역은 기본 접힘이며 필요할 때 펼칠 수 있음
- 전체 ZIP 백업·체크섬 검사·복원 전 자동 백업·관리자 복원
- Supabase Auth 로그인, 현장별 관리자/편집자/조회자 권한과 RLS

## 실행

Node.js 22 이상 및 pnpm 11.25 이상을 사용합니다.

```sh
pnpm install
cp .env.example .env.local
pnpm dev
```

Windows에서는 `.env.example`을 `.env.local`로 복사합니다. 개발 서버 주소는 `http://127.0.0.1:5173/`입니다. 개발 서버는 PC 내부에만 연결됩니다.

환경변수:

```ini
VITE_SUPABASE_URL=https://your-project.supabase.co
VITE_SUPABASE_ANON_KEY=공개_publishable_또는_anon_키
```

공개 키는 클라이언트에서 사용하는 키입니다. **service_role, secret 키, DB 비밀번호는 사용하지 않습니다.** 설정 화면에서도 프로젝트 URL과 공개 키를 입력할 수 있습니다. `.env.local` 및 원본 파일은 Git에 포함하지 않습니다.

## Supabase 최초 설치

1. Supabase SQL Editor에서 [전용 설치 SQL](supabase/setup.sql)을 한 번 실행합니다. 기존 `mm_` 설치가 있으면 중단합니다.
2. Authentication → Users에서 사용할 계정을 등록합니다. 기존 프로젝트의 로그인 설정·사용자는 변경하지 않습니다. 이 프로그램에서는 공개 회원가입을 제공하지 않습니다.
3. 앱에서 로그인한 뒤 현장을 생성합니다. 생성한 사용자가 해당 현장의 관리자가 됩니다.
4. 다른 사용자는 Supabase Authentication에 등록한 뒤 앱의 설정 → 연결·사용자에서 사용자 UUID와 권한을 추가합니다.
5. 로컬 확인 자료를 옮기려면 같은 브라우저에서 공유 모드로 로그인한 뒤 설정 → 연결·사용자 → ‘로컬 자료를 공유 저장으로 가져오기’를 사용합니다. 또는 로컬 모드에서 전체 백업 ZIP을 받고, 공유 모드에서 관리자 권한으로 복원합니다. 기존 공유 자료는 자동 백업 후 교체됩니다.

### 기존 사이트와 같은 Supabase 프로젝트를 쓰는 경우

추가하는 테이블: `mm_projects`, `mm_members`, `mm_records`, `mm_audit`, `mm_operations`. 함수도 `mm_` 접두사를 쓰며, 파일 버킷은 비공개 `mm-files`입니다. 기존 테이블·함수·RLS 정책·Auth 설정을 변경하거나 삭제하지 않습니다. 업무 데이터는 Vercel 파일이나 GitHub에 저장하지 않습니다.

프로젝트 용량·트래픽·Auth 사용자 목록은 공유됩니다. 기존 `storage.objects` 정책이 모든 버킷에 광범위하게 적용된다면 새 버킷에도 영향을 줄 수 있습니다. 설치 전에 다음 **읽기 전용** 조회로 기존 정책을 확인하세요. 기존 정책의 변경은 이 설치에 포함되지 않습니다.

```sql
select policyname, roles, cmd, qual, with_check
from pg_policies
where schemaname='storage' and tablename='objects';
```

다른 사이트 정책이 버킷 범위를 제한하지 않는 경우에는 해당 정책을 검토하거나 별도 Supabase 프로젝트 사용을 권장합니다. 전용 데이터 테이블은 자체 RLS로 현장 간 접근을 제한합니다.

## 로컬 확인 모드

개발 서버에서 `?mode=local`로 들어가면 원본 자료를 브라우저 IndexedDB에 저장해 기능을 확인할 수 있습니다. `?mode=cloud`로 공유 모드에 돌아갑니다. 로컬 변경은 자동으로 Supabase에 동기화되지 않습니다. 브라우저 데이터를 지우면 로컬 변경도 지워지므로 전체 백업으로 보관하세요.

현장 원본은 무시된 `private-data/`에만 보관하며 개발 서버의 전용 경로로만 읽습니다. 이 폴더와 개인 데이터는 배포 결과물에 포함되지 않습니다. 운영 배포에서 로컬 원본 엔드포인트 및 모드 전환 URL은 제공되지 않습니다. 연결 정보가 없는 운영 화면은 빈 상태로 시작하며 설정 후 로그인해야 공유 자료를 사용할 수 있습니다.

## GitHub → Vercel

GitHub 저장소 루트가 이 프로그램입니다. Vercel에서 저장소를 가져온 뒤 Framework는 Vite, Build Command는 `pnpm build`, Output Directory는 `dist`를 사용합니다. 위 환경변수 두 개를 Vercel에 등록하세요. Supabase URL은 프로젝트 주소이며 Storage 버킷 URL이 아닙니다.

실제 현장 자료·연락처·백업 ZIP을 저장소에 올리지 마세요. 변경사항을 push하면 Vercel이 새 버전을 빌드하도록 연결할 수 있습니다. Vercel 배포 자체는 계정 연결 후 진행합니다.

## 검증

```sh
pnpm test
pnpm build
```

핵심 처리 및 PostgreSQL 격리 테스트를 포함합니다. PostgreSQL 테스트는 독립된 메모리 DB에서 수행하며 실제 Supabase에는 접속하지 않습니다. 실제 로그인·Storage 정책·운영 DB 저장은 SQL 실행과 계정 등록 후 별도로 확인해야 합니다.

## 구현 범위와 제한

- 등록·수정은 개별 항목 단위입니다. 일괄 수정·입고관리·자동 이메일 발송은 포함하지 않습니다.
- 업체별 대표 연락처와 추가 담당자 이름·전화·이메일을 여러 개 등록하고 수정할 수 있습니다.
- 연락처 원본 재정리는 `기계(연락처)`·`소방(연락처)` 두 시트만 사용합니다. FAX 열의 담당자 이름은 별도 담당자로 분리하고 번호 없는 행·연락처 칸의 회사명은 확인 필요 자료로 보존합니다. 승인목록에만 있는 제조사는 빈 연락처 행으로 만들지 않습니다.
- 연락처를 재정리할 때 이전 전화·팩스·이메일·담당자 정보를 초기화합니다. 기존 청구·승인목록의 업체 ID는 내부 연결용으로 유지해 참조가 끊기지 않게 합니다. 공유 저장으로의 자료 이관은 로그인 후 관리자 기능을 사용합니다.
- 업로드는 시트별로 검토합니다. 다른 시트는 제외 목록에 기록하고 다음 파일 검토에서 별도로 처리합니다.
- 수정본은 기존 값을 자동 덮어쓰지 않고 중복 후보로 표시합니다. 기존 항목을 직접 정정하거나 실제 반복 청구로 새로 등록할 수 있습니다.
- 표준 청구번호는 원문 메타데이터로 보관합니다. 초기 7열 이력에서 알 수 없는 작업위치·신청자·업체를 추정해 채우지 않습니다.
- 원본에는 수량 공란 1행과 음수 수량 2행이 있습니다. 이 값들은 원본 그대로 보존하고 0이나 양수로 바꾸지 않습니다. 신규 입력의 잘못된 수량은 검증으로 막습니다.
- 백업에는 업무 데이터·파일·전체 감사이력이 포함됩니다. 화면에는 최근 500건을 불러오며 백업은 별도 DB 스냅샷으로 전체 이력을 보관합니다. Auth 비밀번호·토큰은 백업하지 않습니다.
- 새 승인 버전은 과거 버전 정보를 보존합니다. 이전 버전에 연결된 청구는 당시 연결 버전과 현재 목록을 구분해 확인합니다.
- 파일 업로드 실패 시 기존 데이터는 유지합니다. DB 확정에 실패한 새 파일은 미연결 상태로 남을 수 있으므로 관리자 보관 정책에 따라 정리합니다. 원본의 덮어쓰기·삭제 권한은 제공하지 않습니다.
- 첫 버전의 엑셀은 15MB·시트 10,000행, 전체 백업은 100MB 파일·압축 해제 250MB까지 지원합니다.

사용 라이브러리: Vite, Supabase JS, SheetJS CE 0.20.3(공식 배포 패키지), fflate. SheetJS는 Apache-2.0 라이선스입니다.
